# F7R automatic history
The database records incoming telemetry about every two seconds, plus lap/status transitions. New game UIDs get separate recordings. No new receiver is needed.
Finished sessions automatically save about two minutes after the first observed winner finish (position1, result_status3). The server checks every30 seconds, so publication occurs roughly2–2.5 minutes after that reading. A session also saves after2 minutes without telemetry, labelled interrupted/feed-ended. This works with the website closed.
An automatically saved interruption resumes capturing if telemetry with that same UID returns, unless an admin has kept or removed it. Completed or explicitly kept recordings remain frozen. Previously recorded sessions have now been auto-saved; data before the recording feature cannot be reconstructed.
Admins and ordinary signed-in drivers can view saved sessions. Guests cannot read history. Telemetry and history use the same persistent Supabase sign-in; sign in once after this update, then remain signed in across pages/reloads until explicit sign-out.
Admins can Keep session, change its name, or Delete session. Deletion removes it from shared driver history and blocks further capture for that UID. Admins can restore it under Removed sessions; this is a recoverable removal, not a permanent purge. Drivers cannot rename/remove/restore sessions.
Observed lap/sector statistics, pit entries, tyre stints and telemetry are available per driver, with full recorded JSON export. Last running order is labelled; official results cannot be invented if packets are missing. Private/missing readings stay unavailable.
Database migration: auto_save_finished_sessions_and_admin_retention, resume_automatically_saved_interrupted_sessions. SQL source: supabase/dashboard-13-automatic-history.sql. Scheduler: f7r-auto-save-sessions (30 seconds), private function f7r_private.auto_save_recordings. Direct client execution is revoked. Only validated publisher uploads reach the capture trigger.
