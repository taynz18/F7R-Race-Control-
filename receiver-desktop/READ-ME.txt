F7R RECEIVER FOR WINDOWS

1. Extract the entire ZIP into a folder on your laptop.
2. Open F7R Receiver.exe. Keep the _internal folder beside it.
3. Sign in with your F7R receiver email and dashboard password.
4. Choose your assigned live race and click Connect receiver.
5. Open the dashboard as an approved admin and switch on Start live telemetry.

Game: UDP Telemetry On, Broadcast On, port 20777, format 2026.
Your game and laptop must be on the same local network.
Close Racing League Tools first, because it normally uses the same port.
Leave Game IP blank for automatic detection. Enter a specific device IP if multiple F1 games run on the network.
If broadcasting does not work, set the game's destination IP to the receiver laptop and turn Broadcast Off.
If Windows Firewall asks, allow the receiver on your trusted private network.

No Node.js or Python installation is needed. Passwords are not saved.
Keep this app open for the race. Disconnect / sign out stops this laptop's receiver.
Dashboard Stop live telemetry pauses uploads without closing the app.
A new in-game session still needs a new assigned F7R live race and reconnecting.

Dashboard: https://taynz18.github.io/F7R-Race-Control-/

USE F7R AND RACING LEAGUE TOOLS TOGETHER
In F7R choose Telemetry connection: Via RLT forwarding. Its listening port becomes 21777.
In RLT keep the main UDP port at 20777. Add a UDP forwarding target with address 127.0.0.1 and port 21777 if both apps run on the same laptop.
If F7R runs on another PC, use that PC's local IPv4 address as RLT's forwarding target instead.
Leave F7R Source IP blank for automatic detection (forwarded packets originate from RLT).
Keep the game's UDP destination/settings feeding RLT on 20777. Connect F7R and enable dashboard telemetry. No router port forwarding is required.
To change connection mode or port, disconnect and sign in again.

IF THE DASHBOARD SHOWS AN OLD RACE
Each F7R race is linked to one in-game session. Changing lobby or moving from qualifying to race can change that session.
A fresh game session needs a fresh assigned F7R race entry. Select that same entry in the receiver and dashboard, then reconnect.
The receiver now reports a new-session mismatch explicitly instead of silently showing Waiting.
